## 4. 填充比例与价格规则

[已核实] 用户已确认以下规则。（E18）

~~~text
f：填充百分数，取整数 15～100，例如 50 表示 50%
L：管理员设置的最低价，对应 15%
H：管理员设置的最高价，对应 100%

未取整单价 = L + (H - L) × (f - 15) ÷ 85
显示单价   = 四舍五入(未取整单价)，单位：元
数量       = 1
清单金额   = 显示单价
~~~

[推断／拟议] 价格上下限使用整数元保存，校验 L ≥ 0、H ≥ L；H = L 时为固定价。若以后需要分单位成本核算，另行扩展。颜色不另加价；第一版填充只影响报价和配置记录，不模拟内部填充结构或重新切片。

[推断／演算示例] 下表仅解释公式，最低价 20 元、最高价 100 元均为示例，不是真实商品价格：

| 填充比例 | 未取整价格 | 最终价格 |
| --- | --- | --- |
| 15% | 20 | 20 元 |
| 16% | 20.941176… | 21 元 |
| 50% | 52.941176… | 53 元 |
| 100% | 100 | 100 元 |

[推断／拟议] 交互规则：

- 滑块和输入框始终同步，初始值 15%，步长 1%。
- 输入空值、非数字、小数或超出范围时明确提示，不显示由无效值算出的价格。
- 调整填充实时更新报价与清单摘要；颜色、填充、价格来自同一份当前配置。
- 四舍五入后的相邻百分比可以同价，这属于所选规则的结果。
- 后台修改价格后，顾客重新读取最新商品数据；复制清单前重新校验可售状态与价格，变更时展示更新结果。
- 清单注明“页面报价，最终以 QQ 确认为准”，不把复制动作显示成订单已提交。

[推断／拟议] 单件配置清单格式：

~~~text
雨泽小鱼的工坊｜选购清单
商品：<商品名称>
编号：<商品编号>
颜色：<颜色名称>
填充比例：<15～100>%
数量：1
报价：¥<整数金额>
商品链接：<当前商品地址>
页面报价，最终以 QQ 确认为准。
~~~

[推断／拟议] 本地阶段分享地址只用于本机预览，界面应明确它不是公网链接。复制失败时显示可手动选择的文本；无 QQ 二维码时后台提示补充，顾客端不展示失效图片。

## 5. 管理员后台与真实保存

[已核实] 后台必须能上传模型、图片，修改价格与上下架；公共色卡按商品勾选。数据及文件应跨页面刷新、关闭浏览器和重启本地服务保留。（E16、E18）

[推断／拟议] 基础后台功能：

| 区域 | 基础操作 | 保存内容 |
| --- | --- | --- |
| 内容列表 | 新建、编辑、查看状态、上下架 | 内容类型、稳定 ID、名称、简介、状态 |
| 作品编辑 | 图片上传与顺序、可选模型、说明 | 图片列表、展示模型引用、文字内容 |
| 商品编辑 | 模型与图片、价格上下限、可用颜色 | 模型引用、L／H、色卡 ID、说明 |
| 公共色卡 | 添加、改名、设置色值、停用 | 颜色 ID、名称、颜色值、状态 |
| 资源管理 | 上传、查看处理状态、替换 | 原件、预览文件、缩略图、处理记录 |
| 联系设置 | QQ 二维码上传、预览、更换 | 二维码图片引用 |
| 数据状态 | 保存成功／失败、未保存变更 | 以实际服务端保存结果显示反馈 |

[推断／拟议] 保存结构采用“本地 API＋SQLite 数据库＋磁盘文件目录”。SQLite 保存记录与文件引用，磁盘保存图片、原始模型和展示文件；浏览器存储只用于界面偏好，不承担商品数据库。

[推断／拟议] 管理流程：

~~~text
创建内容 → 选择作品／商品 → 填写信息与上传素材
        → 商品设置 L／H 和可用色卡
        → 预览检查 → 设为上架 → 顾客端读取最新数据
~~~

[推断／拟议] 状态与一致性规则：

- 内容发布状态分“草稿／上架／下架”，与资源的“待处理／处理中／可用／失败”分开。
- 本地“上架”表示在本地顾客页面可见，不表示已部署互联网。
- 图片型作品可不附模型；商品的 3D 资源未就绪时保留草稿并提示补齐。
- 停用被引用色卡时先展示影响，不让已上架商品出现空选项。
- 替换模型或图片先保存并检查新文件，成功后更新引用；失败保留原可用版本。
- 若浏览器或服务异常退出，重开后保留已成功保存的记录；未保存编辑明确标记。
- 重试上传／保存不应重复创建条目，保存失败不能显示成功。

[推断／拟议] 第一版本地服务仅绑定本机回环地址，后台不向局域网开放；写入接口校验本机会话及请求来源。以后开放远程管理时再加入完整账户与权限设计。（依据 E19）

## 6. 3MF 资产与颜色预览

[已核实] 文件来源为 Bambu Studio，用户选择先用真实 3MF 验证方案，样本待补。（E18、E19）

[已核实] model-viewer 官方示例支持 GLB／glTF、交互相机及材质基础色修改。3MF 官方规范包含网格、组件与变换；lib3mf 提供 3MF 读取、写入及验证能力。这些不能直接证明某份 Bambu Studio 文件已能转换成正确的网页模型。（E8、E9、E11、E17）

[推断／拟议] 优先评估“原始 3MF → 提取所需几何／变换 → 生成展示 GLB → model-viewer 预览”。lib3mf 是读取候选之一，GLB 导出工具链另行验证；不预先承诺自动转换所有文件。

[推断／拟议] 样本验证步骤：

1. 记录来源、文件大小、实际对象及预期外观。
2. 检查文件中可读取的模型、组件、变换及所需扩展。
3. 明确当前商品对应哪些对象；文件里有多件排盘时，不把整盘误作单件商品。
4. 核对模型单位、方向、部件位置、表面和显示完整性。
5. 生成 GLB 与封面，在网页旋转、缩放并切换整体颜色。
6. 验证手机性能与加载失败行为，再决定自动转换、辅助转换或另传 GLB 的上传流程。

[推断／拟议] 原始 3MF 与展示用 GLB 分目录保存；顾客端只请求展示资源，不提供源文件购买／下载入口。预览资源会传输到浏览器，精简模型不等于让模型不可获取。

[推断／拟议] 商品整体换色作用于应变色的模型表面，灯光、地面和背景保持不变。优先使用中性展示材质，避免原有贴图让所选颜色失真；贴图或特殊材质的处理根据样本确认。公共色卡同时展示色块和色名。

[推断／拟议] 性能与异常处理：

- 目录用图片，不为每张卡片初始化 3D；打开详情时只加载当前模型。
- 先展示封面，再加载 3D；提供加载状态、失败说明和重试。
- 3D 不可用时仍显示图片与商品文字，运行时加载失败不抹去当前配置。
- 快速切换页面时取消旧请求或忽略过期结果，离开后释放实例和监听。
- 手机不默认持续自动旋转；重置视角恢复可用的初始位置。
- 色差说明结合实际色卡与材质图片；不承诺屏幕颜色与实物完全一致。

[待验证] 转换覆盖范围、模型体积上限、帧率与加载时间目标，须取得样本和测试设备后定。此阶段没有真实模型转换测试结果。
